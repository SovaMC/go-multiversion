# Minecraft 1.26.60.30 native upgrade preparation

Preview 1.26.60.30 was released on 2026-10-06 with protocol 2225.
[The source lock](1.26.60-preview.30-native.yaml) records the exact revisions,
local candidate, BDS archive metadata and validation boundary.

The original gophertunnel native candidate is `8fe51a2`. It merges upstream
`28a5eec` onto fork `4ea1495`, preserving the prior NetherNet HTTP signaling and
legacy transport work. Its only source change is CurrentProtocol 2223 to 2225.
The candidate is now reachable through published `codex/dual-transport` commit
`4d6bffd`, which also adds listener lifecycle fixes. This repository now pins that
published revision. The combined work branch is `feat/all_26_u6` across consumers.

## Exact comparison

All 1,014 official JSON schemas were compared between Mojang commits `d702218`
and `b484395`. The comparison removes only the top-level release/protocol metadata
fields, retaining field ordering, types, enum values and numeric constraints.
[The comparison report](1.26.60-preview.30-schema-diff.json) records the result.

| Surface | Change | Adapter impact |
| --- | --- | --- |
| RequestNetworkSettings | ClientNetworkVersion 2223 to 2225 | Native negotiation identity; no field layout change |
| CurrentCmdVersion | Remove SameActorBlockReplacementRetainsItemsFix=55; Latest 56 to 55; Count 57 to 56 | Semantic enum rollback; the fork declares no corresponding enum constants |
| LevelEvent developer notes | Remove IDs 9817 through 9820 | These values are not declared by this fork; no constant removal is needed |
| Other packet/supporting schemas | No changes after release metadata normalization | Existing direct historical conversions retained |

The command-version rollback must not be interpreted as permission to rewrite
arbitrary historical command versions to Latest. There is also an inherited
source/schema discrepancy: upstream gophertunnel represents CommandRequest.Version
as a string, while the official schema references an int32-backed enum. Both .29
and .30 have that discrepancy. This upgrade preserves upstream's codec and records
vanilla command-packet validation as outstanding before claiming command compatibility.

## Validation and data

The fork passed its full local tests, vet and build. go-multiversion passed full
tests and vet with the committed .29 dependency, and full tests, vet and build with
the local .30 candidate through disposable module files. A separate executable
probe required both protocol.CurrentProtocol and minecraft.DefaultProtocol.ID() to
be 2225 and checked RequestNetworkSettings's big-endian body `000008b1`.

Preview wire regression guards explicitly permit the published 2223 baseline and
the validated 2225 candidate, so ordinary CI remains reproducible before fork
publication. This does not add a .29 client adapter when 2225 becomes native.

The checked axolotl-pm/BedrockData preview branch remains at `5f3cd97`, whose
metadata declares .29 / 2223. `data/native2223` retains that original identity.

The [new .30 acquisition](../data/native2225/README.md) comes from locally running
the exact SHA256-verified official Linux BDS in a loopback-only namespace. Vanilla
packets provide 2,080 items, 1,980 creative entries, 89 biomes and the captured
CraftingData vectors. After user approval, a script-only extraction pack enumerates
native blocks and uses BDS structure NBT serialization. Twenty API-normalized
states are recovered through explicit native structure round-trips, not copied as
unverified .29 outputs. The resulting 23,960 typed block records match .29 exactly;
all 1,020 creative block hashes resolve. This proves equality of those block
records, not all registry data or recipe semantics. [Source locks](../data/native2225/source.json)
and [validation counts](../data/native2225/validation.json) record the boundary.

The [BDS catalog copy](1.26.60-preview.30-bds.json) supplies archive URLs and hashes.
Both archives were downloaded and checked; only the Linux build was executed.
No BDS executable, world database or runtime log is committed. Reproducible
extraction source lives under [tools/extract_native2225](../tools/extract_native2225/README.md).

The [offline NBT converter](../tools/normalize_native2225/README.md) now generates
creative/crafting/smithing/potion assets using the existing loader schemas, a typed
modern biome snapshot, and entity NBT. Extra native wire fields live separately in
`packet_metadata.nbt`. The new data accessors restore those fields and pass full
packet reconstruction against the capture. Furnace families are present in the
captured shapeless vector; the earlier missing-furnace classification is corrected.
See [normalization.json](../data/native2225/normalization.json) for hashes/counts.
This prepares loadable data without installing it into a production registry.

The integration now exports these assets with `tools/export_native2225`, including
the Dragonfly data-driven-block container conversion and a provenance manifest.
The matching Dragonfly native adapter uses canonical block hashes: the extracted
alphabetical file order is never treated as vanilla numeric runtime order. The
outgoing 2193 adapter freezes Dragonfly `92ccc8e` data in `data/v2193` and maps
directly to the native registry. Generic mapping handles newly derived connection
properties when upgrading and downgrading states.

Local downstream fork changes still require publication before immutable consumer
pins can be updated. Mojang-client command packets, authenticated login, public
regional Transfer and external ICE reachability remain separate validation gates.
No production deployment is implied by these source checks.
